## 1. 现状：英文能不能显示？（能，已做成判据）

| 项 | 结论 | 依据 |
|---|---|---|
| 字库覆盖 | ✅ **全覆盖** | `tools/mkfont.py` 收 `cps.update(range(0x20, 0x7F))`；实测 `font.bin` 里 95 个 ASCII 可打印字符**一个不缺**、advance 全非 0、抽样字形（A/a/g/W/1/@）非空白 |
| 断行 | ✅ **按空格优先** | `text.c:first_line_bytes()` 对拉丁词先记 `last_space_after`，断在空格；一个词本身超宽则硬断（所以长 URL 会被切断，但不溢出） |
| 禁则 | ✅ | 收尾标点不落行首（`is_no_line_start`）对英文同样生效 |
| 构建期守卫 | ✅ | `tools/check_font_aa.py` 新增 **D 条**：缺字 / advance=0 / 空字模三条判红，并带**反向自测**（故意少 A + g 零宽，必须报出来） |

**结论：思考内容、模型名、动作名、卡上路径这类英文，现在就能正常显示。**

## 2. ✅ 已完成（2026-10-17）

**818 条界面文案全部抽成中英双表，可在设置里切换**（默认中文，老用户升级不变）。

### 机制
- `shared/uistr.h` / `uistr.c`：运行时取文案（`uistr(id)`），越界回中文。
- `shared/uistr_ids.h`（生成）：编号是 **enum** —— 源码里 `S(S0160)` 展开成
  编译期常量下标，所以**写错编号是编译错误**，不是运行时越界。
- `shared/uistr_table.c`（生成）：`g_zh[]` / `g_en[]`。
- 配置项 `ui.lang`（`"zh"` / `"en"`），存进 `config.json`。
- 设置屏「语言」行：左右键切，**立刻落盘**（照 `cycle_theme()` 的做法）。

### 三条纪律
1. **编号是位置不是内容**（与 `game_id` 同纪律）：改文案要重跑
   `tools/i18n_extract.py --apply`，**不要手编表**。
2. **诊断输出不走文案表**：`app_note()` / `boot_mark()` / `actions_audit()` /
   探针 `printf` 里的中文是**验收判据的输入**，翻了会让回归全红而红的
   原因不是功能坏了。抽取脚本按调用点自动跳过。
3. **动作协议名永不翻译**：`file.write` 这类 token 在译文里必须逐字相同。

### 判据（都已挂 `build.py`，判红即停编译）
- `tools/check_i18n.py`：占位符**个数与顺序**一致 / 协议名未翻 / 译文无残留中文。
  带 `--selftest`（三条坏译文必须判红 —— 没有自测的判据是永远绿的假守卫）。
- `tools/i18n_table.py --selftest`：C 字符串转义四条（换行 / 反斜杠 / 引号 / 制表符）。
- 术语统一见 `docs/英文版术语表.md`。

### 踩过的坑（改文案时会再遇到）
- `S()` **不能放在静态初始化**里（它是函数调用）→ 静态表改存编号
  `static const short T[] = { Sxxxx, 0 }`，取值 `T[i] ? S(T[i]) : "字面量"`。
- 相邻字面量拼接放不下 `S()`：`"前半句，" S(S0123)` 要先合并成整句
  （`tools/fix_concat.py`）。有跨行 / 同行 / 三元三种形态。
- 纯文本当格式串用会被 `%` 坑：`snprintf(out, n, "%s", S(...))`。

## 4. 红线（一条都不能松）

1. **动作协议名永远不变**（`file.write`、`sha256=`、`tid=`…），换语言也不换。
   `check_i18n.py` 的 B 条已经在盯这条。
2. **路径不来自 AI** —— 与语言无关，但英文版手册里那条红线必须原样保留。
3. **确认屏的按钮文案是编译期常量**（三道闸之三）：英文版同样**不许**
   用模型给的文本 —— 否则模型能把确认框伪装成别的样子。
4. **判据不许绑文案**（尚未做，见 §3）。
5. 英文版与中文版共用**同一份安全模型**：三道闸 + 白名单 + 审计流水，
   不因为换了语言就有第二个实现。

## 6. ★ 版面硬限制（改英文文案前必读）

宽度是**像素**算的，不是字符数：中文全角 advance=16，英文半角约 8。
所以"英文比中文长"在字符数上成立，在像素上不一定 —— 英文要更宽，
字数得超过中文的 2 倍。

真实容器宽度（从源码读出来的，别猜）：

| 位置 | 容器宽 | 英文上限 | 出处 |
|---|---|---|---|
| 主页 kv 标签列 | **72px** | **8 字符** | `sc_home.c` 的 `w_kv(x,y,78,...)`（内部减边距） |
| 主页按钮 | **86px** | **10 字符** | `HOME_BTN_W 92`（内部减边距） |
| 主页提示行 | **184px** | **23 字符** | `sc_home.c:453` 的 `w_line` |
| 顶/底屏整行 | 300px | 37 字符 | `W_TOP_USABLE` / `W_BOT_USABLE` |

已按这些上限压过的词（**别再改回去**）：
`Launch / Backup / AI / Safety / UI`（kv 标签）、
`Chat / Guides / Update / PC files`（按钮）、
`Arrows pick  A open  X set AI`（提示行）、
`[A]Chat [X]AI [Y]Note [R]Upd [L]Set [ZL]Guide`（页脚）。

判据：
```bash
python tools/check_i18n_layout.py        # 静态体检（秒级，先跑这个）
# 再把 SD 里 config.json 的 ui.lang 改成 "en"，跑一趟 B：
python tools/azahar_test.py --passes "B"
# status.txt 里 layout_overflow 必须是 0
```
`layout_overflow` 只记**最后一条**溢出明细，所以静态体检 + 运行判据要一起用。

## 8. AI 设置项与引导语言选择（2026-10-17 下午）

### 引导：第 1 步就是选语言（4 步流程）
`SCREEN_WELCOME` 从 3 页变 4 页，新页在最前（`g_page == 0`）：
两个按钮 `中文` / `English`，选中的用主色填充；←/→ 或 ↑/↓ 切换，
**切完立刻重画**（`uistr_set_lang` 之后下一帧全部文案就变），
按 A 落盘 `ui.lang` 并进下一步。

为什么单独占一屏：它是唯一一个"选错了整屏都看不懂"的选项 ——
后面每一步的操作提示都靠文字表达。

### 设置屏新增 4 项（AI 段，紧跟"思考强度"）
| 项 | 取值 | 真实作用 |
|---|---|---|
| **AI 记忆** | 一段文本（≤200 B），按 A 用 swkbd 编辑 | 每次请求拼在 system 里，标记 `[About the user]` |
| **回复长度** | 短 / 中 / 长 | → `max_tokens` 300 / 600 / 1200 |
| **上下文轮数** | 4 / 8 / 12 | 发给模型的 history 条数（只裁剪，不删记录） |
| **回答语言** | 跟随界面 / 中文 / English | 拼进 system：`Reply in Chinese./English.` |

设置屏总行数 18 → **22**（版本号仍在语言行之前，但索引从 16 变 20）。

### 实现要点
- `config.h`：`CONFIG_MAX_MEMORY 200`、`CONFIG_REPLY_SHORT/LONG`、`CONFIG_CTX_MIN/MAX`；
  `AiCfg` 加 `memory[200]` / `reply_len` / `context_turns` / `reply_lang`。
- `config.c`：默认值（中 / 8 轮 / 跟随界面）+ `config_clamp` 夹取 + JSON 读写 4 个键。
- `chatapi.h/.c`：`ChatCtx.max_tokens`；JSON 拼装改成"先 model、再可选 max_tokens、
  最后开 messages 数组"—— 早先一整条 snprintf 拼到底，加字段就得整句重排。
- `sc_chat.c`：`g_sysprompt` 缓冲加大（人设 + 记忆 + 手册 + 动作结果 + 语言指令）；
  轮数裁剪 `turns + from`；探针改报 `history=%d/%d mt=%d`，可从 status.txt 验证。

### ★ 这轮踩到的两个坑
1. **`str.replace` 静默失败**：按缩进猜锚点，匹配不上也不报错 ——
   症状是"标签显示对了、值是错的"（取值 case 没插进去，落到 default）。
   → 改代码后必须 `grep` 确认每个 case 都真的在。
2. **判据绑文案，英文模式才爆**：`ui_theme_active == "黑夜"`，
   英文下变成 `Night`，K 趟直接红 —— 而功能是好的。
   → 断言改成 `in ("黑夜", "Night")`。这正是 §3 待办里"判据解绑文案"的实例。
