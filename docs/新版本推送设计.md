# 新版本推送设计

> 状态：**离线通道 ✅ 已实测可用**（2026-10-17 验收趟次 E 全绿）；
> **在线检查 📐 设计态**（`shared/ota.c` 里的 `kUpdateBase` 目前是
> `https://example.invalid/aiconsole` —— 占位符，没有任何代码去拉它）。
>
> 本文先回答"现在能不能升级"，再给"怎么把新版本推给用户"的方案。

---

## 0. 检测结论：OTA 能不能用？

**能用。** 2026-10-17 实测（趟次 E）：卡上放一个 v100 的离线包 →
app 扫到 → 校验 size + sha256 → 按 A 安装 → **目标文件真的被写出**，
大小与 manifest 声明一致（断言 `e_installed_size` 通过）。

过程中踩到的那个"看起来坏了"的坑值得记下来：

| 现象 | 真因 |
|---|---|
| E 趟红：`end_screen` 不是 `SCREEN_UPDATE`、`e_installed_size=None` | 验收用的假包版本号**写死 99**，而程序版本也是 99 → app 正确判定「已经是最新」，根本没进可安装状态（截图上是"已经是最新 —— 包里是 v99，和当前一样"） |

**结论：不是功能坏了，是夹具过期。** 已把夹具改成"从 `shared/ota.h` 现读版本号 +1"，
从此改版本号不会再把这条判据拖红。

> 这类失败的危险之处：它长得完全像"功能崩了"。
> 排查时**先看屏幕上的字**（"已经是最新"vs"摘要不符"），再看代码。

## 1. 现状能力（每一项都对应代码里的实现）

| 能力 | 状态 | 实现位置 |
|---|---|---|
| 识别卡上的更新包 | ✅ | `ota_scan_local()`：读 `SD:/3ds/aiconsole/update/manifest.json` |
| manifest 解析 | ✅ | `ota_parse()`，schema=1 |
| 版本比较（拒降级） | ✅ | `ota_compare()`：1 有更新 / 0 一样 / -1 更旧 → 拒绝 |
| 逐产物 size + sha256 校验 | ✅ | `ota_scan_local()` 里循环 `art[]` |
| 3dsx 覆盖安装 | ✅ | `ota_install()`：写到 `SD:/3ds/AIConsole.3dsx` |
| CIA 处理 | ⚠️ **只复制，不自装** | `ota_install()`：复制到 `cias/`，并提示"去 FBI 里点一下" |
| 启动时提醒 | ✅ | 只提示、**绝不自动安装** |
| 完整说明页 | ✅ | `notes.html` 内置查看器（HTML 子集） |
| **在线检查新版本** | ❌ **未实现** | `kUpdateBase` 是占位符 |

### 为什么 CIA 不能自装（这条是硬限制，不是没做）
装 CIA 走 `am:u`（AM 服务）权限，**自制程序拿不到**。
所以 CIA 形态的更新永远是"我自己把新包放好，你去 FBI 点一下"。
`ota.h` 的注释里已经如实写了这一句 —— 不要在界面上承诺"自动升级"。

## 2. 三条硬限制（设计必须绕开，不能假装不存在）

1. **没有后台、没有推送通道。**
   3DS 没有 FCM/APNs 这种东西，app 不在前台就什么都不会发生。
   → 检查时机只能是「启动时」或「用户按 R 进更新屏时」。

2. **TLS 很老。**
   `httpc` 只支持较老的 TLS 套件，现代 CDN（强制 TLS1.3 / 新证书链）
   可能直接握手失败。`sc_update.c` 里那句"3DS 的老 TLS 未必连得上
   现在这些站点"就是这个意思。
   → 托管必须选**实测能连**的端点（本项目已知可用：`api.deepseek.com`、
   `api.siliconflow.cn`；静态托管要另外实测）。

3. **包不小。**
   3dsx ≈ 5 MB、CIA ≈ 3.7 MB。3DS 的 Wi-Fi + httpc 下这是"要等一会儿"的量级。
   → **必须用户主动触发**，不能启动时偷跑后台下载；
   下载要能显示进度、能中断。

## 3. 推送方案（三层，按"能不能落地"排序）

### L1 · 离线包通道（✅ 现在就可用，最稳）

```
发布者:  build → 打包 → 手动/脚本放上卡
用户:    SD:/3ds/aiconsole/update/
             ├── manifest.json
             ├── AIConsole.3dsx
             └── notes.html        （可选，更新说明）
         app 内按 R → 看到版本与说明 → 按 A 安装
```

**适用**：能摸到 SD 卡的用户（自制机用户基本都是）。
**优点**：零网络依赖、零服务器成本、**已实测**。
**这是当前唯一真正可用的通道**，下面两层都是它的延伸。

### L2 · 在线检查 + 用户确认后下载（📐 建议下一步）

分两步，**检查便宜、下载昂贵**：

```
① 检查（几百字节）
   启动时（或按 R）: GET {base}/manifest.json
        → 比较 version_code
        → 有新版本：主界面顶部提示一行「有新版本 vN，按 R 看」
        → 失败（超时/TLS 握手失败）：静默，不打扰用户
   
② 下载（几 MB，必须用户按）
   更新屏按 A: GET {base}/{artifact.file}  →  写到 update/ 临时文件
        → 逐块喂 sha256（边下边算，不额外读一遍）
        → 校验通过后 rename 成正式文件名
        → 然后走**现有**的 ota_scan_local + ota_install 链路
```

★ **关键决定：下载与安装分成两个动作。**
理由：下载失败（网络断了、TLS 不通）和安装失败（摘要不符、写不进卡）
是**完全不同的事**，用户需要能分辨。合成一步的话，
失败提示只能写成"更新失败"，那等于没提示。

**要不要新增代码**：需要。`shared/ota.c` 里加一个
`bool ota_fetch_manifest(const char *url, OtaManifest *m, char *err, size_t cap)`，
复用现有的 `httpx` 那一层。下载用 `ota_install` 之前先落盘到
`update/.partial`，校验完再 rename（**不要直接写目标文件**，见 §5 第 5 条）。

### L3 · 全自动升级（❌ 做不到，别设计）

- CIA：无 `am:u` 权限 → 不可能自装。
- 3dsx：理论上能替换自己，但**正在运行的文件被自己覆盖**是找死
  （文件句柄、代码段已映射）。
  唯一稳的做法还是"写新文件 → 下次启动生效"，即等价于 L2。

## 4. manifest 规范（app 真正认的字段，不是设想）

生成工具：`python tools/make_manifest.py`
（从**真实产物**算 size/sha256，避免手写出错）

```json
{
  "schema": 1,                 // 必填，当前只认 1
  "version_code": 100,         // 必填，整数，比较用
  "version_name": "0.99",      // 必填，显示用（≤24 字节）
  "channel": "stable",         // 必填，stable / beta
  "min_supported": 99,         // 必填，低于它的旧版需先升中间版
  "notes": "一句话说明",        // 必填（可空串），≤192 字节
  "artifacts": [               // 必填，1..4 个（OTA_MAX_ARTIFACTS=4）
    {
      "kind": "3dsx",          // 3dsx / cia
      "file": "AIConsole.3dsx",// 与 manifest 同目录
      "install": "replace",    // replace=覆盖当前程序 / copy=只放进 cias/
      "size": 5114072,
      "sha256": "c23bb4be…"
    }
  ]
}
```

约定：
- `version_name` 与 `shared/ota.h` 的 `APP_VERSION_NAME` 同源（脚本自动读）。
- 一个包同时带 3dsx 和 cia 是允许的；app 按当前形态挑能装的那个。
- `notes.html`（可选）是给人看的详细说明，走内置查看器。

## 5. 安全红线（一条都不能松）

1. **sha256 必校，且来自发布侧。**
   不能只信包内自述 —— 包内自述等于让被篡改的包自己说"我是合法的"。

2. **拒绝降级。**
   `version_code <= 当前` 一律不装。降级通道是攻击面（回退到有漏洞的旧版），
   而且用户没有任何理由需要它。

3. **`min_supported` 防跨版本破坏。**
   存储格式 / 配置 schema 变过的时候，老版本直接跳到最新版可能读坏数据。
   这时把 `min_supported` 设成"能安全跨越的那个版本"。

4. **CIA 的 Title ID 白名单。**
   ★ 这条有血泪教训：本项目曾用 `0xF8001` 与 FBI 官方 Title ID
   `000400000F800100` **撞号**，装上去就把人家的程序顶掉了。
   CIA 产物在校验阶段必须**解析并比对 Title ID**，不是自己的直接拒。

5. **原子替换。**
   先写 `.partial` / `.tmp`，校验通过再 `rename`。
   直接往目标文件写，断电 = 半个二进制 = 变砖。

6. **装前留退路。**
   被覆盖的旧文件先改名 `.bak`（保留一份），装完确认成功再删。
   装失败时用户至少还能把旧的改回来。

7. **永远不自动安装。**
   检查可以自动，安装必须用户按 A。这条与三道闸是同一个精神：
   **AI 和自动化都不能替用户做不可撤销的决定。**

## 6. 发布流程（现在就能照着做）

```bash
# 1) 改版本号（唯一真源）
#    shared/ota.h:  APP_VERSION_CODE 99 -> 100
#                   APP_VERSION_NAME "0.99" -> "1.00"

# 2) 构建 + 打包
python tools/build.py cia          # 出 app/AIConsole.{3dsx,cia}
python tools/make_pack.py          # 出 dist/AIConsole-<ver>-pack.zip

# 3) 生成 manifest（size/sha256 现算）
python tools/make_manifest.py \
    --notes-file RELEASE_NOTES.md \
    --out dist/manifest.json

# 4) 发布（二选一）
#    a. 离线通道：把 dist/ 里的 manifest.json + 产物 + notes.html
#       整体复制到 SD:/3ds/aiconsole/update/
#    b. 在线通道（L2 落地后）：同一组文件上传到 https://<base>/aiconsole/
#       —— 目录结构保持一致，客户端就只是换了个来源

# 5) 验收（务必）
python tools/azahar_test.py --passes "E"
#    E 趟会现造一个"版本号 = 当前+1"的包，验证 识别→校验→安装 全链
```

★ 第 3 步的脚本会**拒收**几种情况（都是实际会犯的错）：
- 一个产物都没有；
- 产物超过 4 个（app 只读前 4 个）；
- `--version-code` 手填得比 `shared/ota.h` 还小（发出去会被判降级）。

## 9. 在线通道已落地并端到端验证（2026-10-17）

### 代码（`shared/ota.c` + `app/source/ui/sc_update.c`）
| 函数 | 作用 |
|---|---|
| `ota_fetch_remote(channel, ...)` | GET `{base}/{channel}/manifest.json`，几百字节，解析 + 比版本 |
| `ota_download(channel, m, idx)` | GET 产物 → 写 `.partial`，**边下边算 sha256**，校验过才 rename |
| `ota_remote_raw(&n)` | 交出上一次读到的 manifest 原文（下载完要原样落盘） |

更新屏按键：**SELECT** = 在线检查；线上有新版时 **A** = 下载（下完再按 A = 安装）。
`Y` 仍是"重新扫卡"，没被占用。

### 端到端验证（真跑过，不是"应该能行"）
做法：本机起 `python -m http.server 18999` 提供 `/aiconsole/stable/`，
构建时注入 `AIC_EXTRA_CFLAGS='-DOTA_BASE_URL="http://127.0.0.1:18999/aiconsole"'`，
跑改造过的 E 趟（SELECT → A 下载 → X 说明 → 右键 → A 安装）。

程序自己的 note（`status.txt`）：
```
ota: online check state=3 ch=stable detail=线上 v9.9-online 可用（1 个产物）
ota: manifest synced 385 bytes
ota: downloaded 1/1 -> state=4          ← 4 = VERIFY_OK
ota: installed AIConsole.3dsx
```
断言全绿（10 张截图）：`end_screen=SCREEN_UPDATE`、文件已写出、
**大小与 manifest 声明一致（1000 字节）**、`layout_overflow=0`。

### ★ 这轮抓到的两个真 bug（都已修）
1. **下载后没同步 manifest。**
   下载了新产物，但卡上的 `manifest.json` 还是旧的 →
   `ota_scan_local` 拿旧 size/sha 核对新产物 → 必然"大小不符" →
   用户看到"包坏了"，其实是**我们没同步 manifest**。
   修：`ota_fetch_remote` 留一份原文，下载全成功后写到 `update/manifest.json`。
2. **断言取错根**（测试侧）。大小断言遍历候选 SD 根取第一个命中，
   拿到别的根里的旧夹具（1320 vs 实际 1000），报错方向完全反。
   修：用 `e_installed_root`（按 status.txt 反推的生效根）——
   这与 `run_pass` 里早就改过的同一个坑是同一件事。

### 为什么 E 趟**没**保留在线流程
日常回归不能依赖外部服务：断网即全红，而红的原因与代码无关。
所以 E 趟仍是**离线**流程（卡上夹具）。在线链路按上面四步手动验证，
或用 `AIC_EXTRA_CFLAGS` 注入端点后临时改 `SCRIPT_E`。

### ⚠️ 仍未验证的一件事（必须真机做）
**3DS 真机的 TLS 握手**。模拟器（Azahar）的 httpc 走宿主网络栈，
TLS 是宿主实现的 —— 所以"模拟器能连"**不代表真机也能连**。
上面那次验证用的是 **HTTP**（绕开 TLS），只证明协议链路正确。

真机验证方法：拿 CIA 到真机 → 进更新屏 → 按 SELECT。
若显示"连不上更新源"，就是 TLS/证书链问题，需要换托管端点重试。
注意 `httpcSetSSLOpt(SSLCOPT_DisableVerify)` 已经关掉了证书校验
（3DS 无根证书库），所以**能连不上通常是套件/协议版本不匹配**，不是证书。

## 7. 待实现（L2 的代码清单）

| 项 | 工作量 | 说明 |
|---|---|---|
| `ota_fetch_manifest()` | 小 | 复用 `httpx`，GET + 解析，超时 8s，失败静默 |
| 更新屏加"在线检查"一栏 | 小 | 显示"线上最新：vN"与最后检查时间 |
| 下载到 `.partial` + 边下边算 sha256 | 中 | 进度条（底屏一行）、可中断 |
| 设置里加"更新通道" | 小 | stable / beta，写 `config.json` 的 `ota.channel` |
| HTTPS 端点实测 | 中 | **必须实测**：候选托管域名在 3DS 上能不能握手 |

⚠️ 第 5 项是**前置条件**：如果目标托管站点和 3DS 的 TLS 握不上手，
L2 整套都是空中楼阁。建议先写个一次性探针（跑一趟模拟器/真机，
只发一个 GET），确认端点可用之后再写下载逻辑 ——
**先验证"能不能连"，再写"连上之后做什么"。**
