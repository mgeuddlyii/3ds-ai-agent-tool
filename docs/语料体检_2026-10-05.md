## 5. 重建时要注意的一件事（来自 `build_kb.py` 的注释）

`MAX_POSTING = 64` 是**在 31 款 / 1174 段**上标定的。它的作用是「每个词最多索引 64 个段落」。
段落总数从 1174 涨到 3143（×2.68）后，**同一个词的 df 会普遍变大**，
原来 df ≤ 64 的词现在可能被截断 —— 症状正是 `build_kb.py` 里写过的那种
「限定游戏检索 0 命中」，不报错、只是答案错。

→ 重建后**必须验一遍「限定游戏检索」**，别只看总命中率。

## 6. 正确的重建顺序（这四步不能省，也不能换序）

```
python tools/guia/gen_game_tables.py --write   # ① 补 g_alias / g_game_names（当前停在 31）
python tools/guia/gen_cand_rows.py             # ② 补 g_cand_set（sc_guide.c，有编译期断言）
python tools/build.py                          # ③ 重建 guide_kb.bin + 二进制
python tools/guia/verify_vocab.py              # ④ 三方一致性
```

⚠️ `--write` 这个参数是**后补的**（原先 docstring 写了、代码里没有 argv，跑完像成功其实一个字节没改）。
跑完①之后**要 `ls -l` 看 `guide_kb.c` 的 mtime 有没有变**，别看"没报错"就当成功。

⚠️ 建议等另一个会话**停止写语料**（现在 `corpus/` 每几分钟多一款）再重建，
否则重建的是一个移动靶，`n_game` 与实际内容又会立刻脱节。
